# 检查点提交与恢复规则

## 提交规则

- 检查点只在下游 `Sink.Write` 确认（返回 nil）之后提交，
  **未被确认消费的记录永远不会被检查点越过**；
- 提交按记录顺序逐条进行，`Seq` 严格单调递增；
- 持久化采用写临时文件 + 原子 rename，进程在任意时刻崩溃都不会留下
  半提交状态；文件内含 SHA-256 校验和；
- 并发提交经互斥锁串行化，最终结果等价于某个串行顺序。

## 拒绝规则（`*CheckpointError`，`Reason` 可区分）

- `regression`：提交的 `Seq` 不大于已提交值（回退或重复提交）；
- `gap`：提交跳过了尚未确认的记录（如已提交 5 却直接提交 7）；
- `corrupt`：持久化文件不是合法 JSON 或校验和不匹配——
  明确拒绝并说明原因，绝不静默从头开始；
- `schema_drift`：恢复时检查点绑定的模式哈希与当前声明不一致。

## 恢复规则

- 重启后从最近一次已提交位置继续：`resume` 检查点原样传给 `Read`，
  连接器可从 `Offset` 恢复读取位置；
- 宿主同时按 `Seq` 去重：`Seq <= 已提交序号` 的记录视为 at-least-once
  重放，直接跳过、不投递下游——恢复后重复出现的记录**不会重复提交，
  也不会漏掉**；
- 恢复点之后的记录必须严格递增，否则按契约违规终止（见契约文档）。

## 可配置项

`host.Options`：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `BufferSize` | 16 | 连接器到下游的有界缓冲容量（背压上界） |
| `ReadTimeout` | 30s | 单次运行的总截止时间 |
| `CancelGrace` | 2s | 取消后等待连接器自行退出的宽限期 |
| `Config` | 零值 | 传给连接器 `Open` 的自定义配置 |

`host.NewCheckpointStore(dir)`：检查点本地存储目录，按连接器分文件存放。

## 本地验证

```sh
go test ./...                  # 全部单元测试
go test -race -count=2 ./...   # 竞态检测，重复两轮验证稳定性
go test -race -v ./host        # 查看各业务场景的用例日志
```

覆盖的业务场景（日志中以 `场景[...]` 标注）：

- 契约不兼容拒绝：重复注册 / 声明缺失 / 声明冲突 / 接口版本不支持 / 模式不兼容演进；
- 隔离：连接器卡住不响应取消、执行中 panic、连接器自身报错归类；
- 背压：下游阻塞时投递停止、内存有界、开闸后按序完成；
- 断点恢复：失败定位检查点、重放去重、无重复无遗漏、模式漂移拒绝；
- 并发：多连接器并发运行进度独立、同工厂实例状态隔离、panic 不波及其它。
